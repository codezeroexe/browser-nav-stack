# Phase 1 — UI Design Contract

> Visual and interaction contract for drastic user-friendliness improvements and personal touch for Browser Navigation System. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## User Personas

| Persona | Description | Goals | Pain Points |
|---------|-------------|-------|-------------|
| **CS Student** | Learning data structures, 18-25, prefers visual learning | Understand LIFO stacks through interactive simulation | Abstract concepts hard to grasp from code alone |
| **Instructor** | Teaching DS&A, wants demonstration tools | Show stack operations live in class | Existing tools are either too complex or too abstract |
| **Curious Learner** | Non-CS background, exploring how browsers work | Intuitively understand back/forward navigation | Confused by "stack" terminology without visual metaphor |
| **Power User** | Developer testing navigation edge cases | Quickly simulate deep navigation paths | Manual URL entry is tedious, no persistence between sessions |

---

## Journey Map

| Stage | User Action | System Response | Emotional State |
|-------|-------------|-----------------|-----------------|
| **First Visit** | Lands on page, sees title + input field | Shows empty state with subtle hint "Enter a URL to start navigating" | Confused — "What am I looking at?" |
| **First URL** | Types URL, clicks Visit | URL appears as current page, Back Stack shows visited page, subtle push animation plays | Aha moment — "Oh, it works like a browser!" |
| **Discovery** | Clicks Back, then Forward | Sees pages move between stacks, LIFO order becomes apparent | Learning — "The most recent goes first" |
| **Understanding** | Visits 5+ URLs, uses Back repeatedly | Sees stack depth grow, understands top/bottom concept | Confident — "I get how this works now" |
| **Mastery** | Explains concept to others, uses tutorial mode | Can predict stack state, uses keyboard shortcuts (Alt+Left/Right) | Empowered — "This is a great teaching tool" |

---

## Design Principles

1. **Show, Don't Tell** — Animate stack operations so LIFO becomes visually obvious without reading text explanations
2. **Progressive Disclosure** — Start simple (just Visit/Back/Forward), reveal depth (stack visualization, tutorial mode) as user explores
3. **Delight in Details** — Micro-interactions (confetti on 10th visit, favicon fetching, subtle stack shadows) make it feel crafted, not generic
4. **Forgiving Interface** — Smart URL validation with suggestions, undo capability via localStorage history persistence
5. **Personal Ownership** — Let users name their session, pick accent colors, see their visit stats — make it *their* simulator

## Feature Specifications

### P0 — Critical (Must Have)

#### F1: Animated Stack Visualization
- **Rationale**: Users don't intuitively grasp LIFO without seeing items physically move between stacks
- **Priority**: P0
- **Mock Description**: Two vertical stack containers side-by-side. When "Visit" clicked, new URL slides up from input into Back Stack with bounce animation. When "Back" clicked, top item slides from Back Stack to Current Page position, Forward Stack gains previous current. Use CSS transforms + Tailwind `animate-fade-in` / `animate-slide-in-from-top`
- **Implementation Hints**: Use `framer-motion` OR CSS `@keyframes` in globals.css. Track `animating` state to prevent double-clicks. Stack items render with `translateY` offset based on index (items lower in stack appear "behind" others with reduced opacity)

#### F2: Interactive Stack Items (Click to Jump)
- **Rationale**: Currently stacks are display-only; clicking a historical item to jump to it teaches LIFO better than buttons alone
- **Priority**: P0
- **Mock Description**: Each item in Back Stack shows clickable cursor. Clicking item X pops items above it back to current, then sets clicked item as current. Confirmation toast: "Jumped to {url} (popped 3 items)"
- **Implementation Hints**: Map through backStack with index. `onClick` calls `jumpTo(index)` which slices backStack and moves popped items to forwardStack. Use shadcn `tooltip` to show "Jump here (pops 2 items above)"

#### F3: Smart URL Validation with Suggestions
- **Rationale**: Current validation is binary (valid/invalid) with no guidance
- **Priority**: P0
- **Mock Description**: As user types, input shows inline suggestion: "Did you mean https://google.com?" when typing "google.com". Invalid URL shows red border + helper text below with example formats
- **Implementation Hints**: Debounced `onChange` handler checks input against common patterns. Maintain `suggestion` state. Use shadcn `input` with `aria-invalid` + description slot for helper text

#### F4: Onboarding Tour (First Visit)
- **Rationale**: 15/24 audit score partly due to unclear first-impression — users don't know what they're looking at
- **Priority**: P0
- **Mock Description**: First-ever visit shows 3-step overlay tour: 1) "This simulates browser back/forward buttons using stacks" 2) "Type a URL and click Visit" 3) "Use Back/Forward to navigate — notice the Last-In-First-Out order!" Dismissable, progress dots, "Skip" link
- **Implementation Hints**: Check `localStorage.getItem('navsim-onboarded')`. Use shadcn `dialog` or custom overlay with `framer-motion` for step transitions. Set flag on complete/skip

#### F5: localStorage Persistence
- **Rationale**: Losing all history on refresh frustrates users who've built deep stacks
- **Priority**: P0
- **Mock Description**: On load, restore `currentPage`, `backStack`, `forwardStack` from localStorage. On each change, serialize to `navsim-history` key. Show toast "History restored" on load if data exists
- **Implementation Hints**: `useEffect` on mount reads localStorage. `useEffect` with deps on all three state arrays writes to localStorage. Use `JSON.parse`/`JSON.stringify` with try/catch

### P1 — Important (Should Have)

#### F6: Favicon Fetching for URLs
- **Rationale**: Visual recognition of websites via favicon makes stack items more scannable and personal
- **Priority**: P1
- **Mock Description**: Each stack item shows favicon (Google Favicon Service: `https://www.google.com/s2/favicons?domain={domain}&sz=32`) next to URL. Fallback to globe icon if fetch fails
- **Implementation Hints**: Create `getFaviconUrl(domain)` helper. Use `<img>` with `onError` fallback to `lucide Globe`. Cache favicons in a `Map<string, string>` state to avoid repeated network calls

#### F7: Visit Count Stats + Achievement Badges
- **Rationale**: Gamification encourages exploration and makes the simulation feel alive
- **Priority**: P1
- **Mock Description**: Small badge in header shows "Visited: {count}" with a trophy icon. Milestones at 5/10/25/50 visits trigger confetti animation (use `canvas-confetti` or CSS particles) + badge earned toast
- **Implementation Hints**: Track `totalVisits` in state + localStorage. Check milestones on each `visit()` call. For confetti, use lightweight `canvas-confetti` npm package or CSS `@keyframes` burst animation

#### F8: URL Drag-to-Reorder (Back Stack)
- **Rationale**: Advanced users want to reorganize their navigation history
- **Priority**: P1
- **Mock Description**: Drag handle appears on hover for back stack items. Drag item to new position in stack, other items shift. Shows "Reordering stacks is not LIFO!" toast as educational moment
- **Implementation Hints**: Use `dnd-kit` or HTML5 drag-and-drop API. On drop, reorder `backStack` array. Disable for forward stack (educational: forward stack shouldn't be manually reordered)

#### F9: Keyboard Shortcuts
- **Rationale**: Power users expect Alt+Left/Right for back/forward like real browsers
- **Priority**: P1
- **Mock Description**: Alt+Left triggers Back, Alt+Right triggers Forward, Enter in input triggers Visit. Show tooltip on buttons: "Back (Alt+←)" 
- **Implementation Hints**: `useEffect` adds `keydown` listener. Check `e.altKey && e.key === 'ArrowLeft'`. Clean up listener on unmount

#### F10: Tutorial Mode (Step-Through Wizard)
- **Rationale**: Structured learning path helps students master concept systematically
- **Priority**: P1
- **Mock Description**: "Tutorial" button opens wizard with 5 steps: 1) Visit a URL, 2) Visit another, 3) Go Back, 4) Go Forward, 5) Clear. Each step highlights relevant UI element with pulse animation, explains what's happening to stacks
- **Implementation Hints**: Use shadcn `tabs` or custom wizard state machine. Highlight targets using `ref` + CSS `box-shadow` pulse. Advance on actual user action (not just button click)

---

### P2 — Nice to Have

#### F11: Accent Color Picker (Personal Touch)
- **Rationale**: Lets users feel ownership over "their" simulator
- **Priority**: P2
- **Mock Description**: Settings gear icon opens popover with 6 color swatches (blue, green, purple, orange, pink, teal). Click sets accent, saved to localStorage, applied via `--user-accent` CSS variable
- **Implementation Hints**: Extend globals.css `:root` with CSS custom property. Use shadcn `popover` + `button` swatches. Read/write `--user-accent` via `document.documentElement.style.setProperty`

#### F12: User Name/Greeting
- **Rationale**: Personal touch — "Welcome back, Hari" feels crafted
- **Priority**: P2
- **Mock Description**: On first visit, prompt (via dialog) for name. Subsequent visits show "Welcome back, {name}!" in header. Skip button for privacy-conscious users
- **Implementation Hints**: localStorage `navsim-username`. shadcn `dialog` with `input` for name entry. Display in CardHeader next to title

#### F13: Export State as Image
- **Rationale**: Students want to save/share their stack state for assignments
- **Priority**: P2
- **Mock Description**: "Export" button captures current view as PNG using `html-to-image` library. File named `browser-nav-stack-{timestamp}.png`
- **Implementation Hints**: Use `html-to-image` npm package. Target the main `div` ref. Trigger download via programmatic `<a>` click with `blob` URL

#### F14: Stack Comparison Mode (Stack vs Queue)
- **Rationale**: Educational — shows what a queue would look like vs stack for same operations
- **Priority**: P2
- **Mock Description**: Toggle switch "Compare: Stack vs Queue". When on, shows a third column simulating FIFO queue alongside the stacks. Same visit/back operations, different order
- **Implementation Hints**: Add `compareMode` state. When on, maintain `queue` array alongside stacks. Render third card. Use shadcn `switch` component

#### F15: Sound Effects (Optional Toggle)
- **Rationale**: Playful micro-interaction for users who want immersive experience
- **Priority**: P2
- **Mock Description**: Settings toggle enables subtle "whoosh" sound on Back/Forward, "pop" on Visit. Volume control, respects `prefers-reduced-motion` and `prefers-reduced-sound`
- **Implementation Hints**: Use Web Audio API or `<audio>` elements. Preload 3 short sounds. Check `window.matchMedia('(prefers-reduced-motion)')` before playing

#### F16: Shareable URL with Embedded State
- **Rationale**: Users can send their stack state to instructors or friends
- **Priority**: P2
- **Mock Description**: "Share" button encodes current state as base64 in URL hash (#state=eyJiY...). Opening that URL restores the state. Shows toast with copyable link
- **Implementation Hints**: `btoa(JSON.stringify(state))` for encoding. `atob()` on load for decoding. Use `window.location.hash`. Max URL length considerations (~2000 chars)

### Animation Guidelines
- **Stack Push (Visit)**: New item fades in at top of back stack, slides down if items exist below
- **Stack Pop (Back)**: Top item slides right to current page position, fades into badge
- **Forward Move**: Current page slides left to forward stack, new page slides in from left
- **Duration**: 300ms ease-out for all transitions (match Tailwind `duration-300`)
- **Respect `prefers-reduced-motion`**: Set `motion-safe:` variants, disable animations if user prefers reduced motion

### Color Enhancements (Beyond shadcn defaults)
- **Stack Items**: Alternating `bg-muted/50` and `bg-background` for readability
- **Current Page Badge**: Uses accent color with `shadow-lg` for prominence
- **Depth Meter**: Gradient from `oklch(0.7 0.15 140)` (green) → `oklch(0.7 0.2 80)` (yellow) → `oklch(0.6 0.25 30)` (red)
- **Achievement Badges**: Gold accent `oklch(0.75 0.15 85)` with shimmer animation

### Typography Details
- **URLs in stacks**: `font-mono text-xs` for readability of domains
- **Card titles**: `font-sans text-lg font-semibold` (from shadcn CardTitle)
- **Educational tooltips**: `text-xs text-muted-foreground italic` for explanatory text
- **Achievement text**: `font-semibold text-achievement` with sparkle emoji
